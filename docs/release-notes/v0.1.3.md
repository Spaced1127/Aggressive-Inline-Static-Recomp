# Aggressive Inline Static Recomp v0.1.3

Level-start stutter fix, plus a simpler controller system that works with any
pad and needs no setup.

## Level loading: the freezes are gone

Players reported that the first seconds of a level were very stuttery, with
the first Movie Lot level the worst. Measured from a save state, Movie Lot froze
for up to 1.6 s, then ran a "staircase" of 100 ms frames, then froze again for
1.3-1.6 s, and was still at only 54 FPS (0.92x speed) 30 seconds into the level.

There were two separate causes:

1. **The game's idle loop was not being skipped.** When nothing is ready to
   run, for example while a level streams from the disc, every GameCube game
   built on Nintendo's SDK sits in a tiny "wait" loop. Dolphin's JIT detects
   that loop and skips ahead to the next event. Our static-recompiled core only
   does this at an address you configure, and this game had none. So it ran the
   loop for real, and that cost more PC time than the console time it
   represents. The longer the game waited, the further it fell behind: 54 FPS
   in Movie Lot. The loop is at `0x80143348` (SDK `SelectThread`). It was the
   single hottest spot in the game, about 30 % of all sampled code, while
   loading.
2. **Emulated disc timing.** The long freezes were exact multiples of the
   60 Hz frame (100.1 ms = 6 frames, 1601.7 ms = 96). The emulator kept up;
   the game itself does not draw while it waits on the emulated disc's
   seek and spin-up times.

v0.1.3 ships `Sys/GameSettings/GILE51.ini`, which the game loads
automatically:

```ini
[Core]
StaticRecompIdlePC = 0x80143348   ; skip the SDK idle loop
FastDiscSpeed = True              ; treat disc reads as buffered
```

Movie Lot, warm shader cache, 30 s after starting the level:

| | worst frame | frames > 50 ms | after 30 s |
|---|---:|---:|---|
| v0.1.2 | 1602 ms | 47 | 54.1 FPS / 0.92x |
| **v0.1.3 (this release build)** | **480 ms** | **14** | **59.94 FPS / 1.00x** |

The remaining short hitches (up to about half a second) all fall within about
3.5 s of starting the level, while the LOADING screen is up. Doubling the
emulated CPU clock did not reduce them, so they are data-transfer waits, not
CPU work, and no overclock is used. The other levels were play-tested after
the fix and felt smooth.

## Controllers: any pad, no setup

- **One standard profile** (`GCPadNew.ini`) is written the first time the game
  runs and is never rewritten. The per-device preset files and the "Read from
  log" step are gone.
- **The connected pad is bound automatically**, in memory. Swap an Xbox pad for
  a DualSense (or anything else SDL supports) and it works on the next launch,
  or within about two seconds if you plug it in mid-game. No config edit is
  needed. Verified live: the profile named a DualSense, an Xbox One pad was
  connected, and the game logged
  `configured device missing; bound "SDL/0/Xbox One Controller"` and played
  normally.
- **The launcher's CONTROLLER page picks only the button class**:
  - Auto (default): Switch Pro, Joy-Con and 8BitDo pads in Switch mode get
    Nintendo; everything else is Positional.
  - Positional: Xbox / PlayStation style.
  - Nintendo: A/B and X/Y swapped to match printed letters.

  The D-pad, sticks and triggers are never swapped. The RecompLauncher
  manifest exposes the same choice.
- Checks: launcher controller self-test 8/8; offline controller layout matrix
  passes (Xbox/Elite, DualSense/Edge, DualShock, 8BitDo USB/BT/Switch/XInput,
  Switch Pro/Joy-Con, generic).

If a pad misbehaves, send the `controller:` lines from `logs\run.log`.

**Upgrading:** an existing `GCPadNew.ini` keeps working; a stale device name
is harmless. If your first launch ever happened with no controller connected,
the profile holds keyboard bindings. Delete it once a pad is connected.

## Cheats

The cheat screen compares **typed text**. Directions are the on-screen
keyboard's arrows and "B A B A" is keyboard letters, not controller buttons,
which is why the codes seemed not to work. Unlock all levels:
↑ ↑ ↓ ↓ ← → ← → B A B A. PLAYERS.md lists the rest. (`PLZDOME`, listed on
some sites, is not in the GameCube version.)
